# Fridge Decision 中文离线演示 v1

状态：编译和上传结果见交接记录；新的演示画面和按键翻页仍需实体验收。
屏幕沿用已实测 GxEPD2_420c_Z96，SPI SCK2/MOSI3/CS7/DC6/RST10/BUSY0，1MHz MODE0，复位2ms，rotation2+mirror。GPIO4/5/13 INPUT_PULLUP，低电平按下，40ms去抖，按住不连发。

页面：先吃这些、今晚吃什么、设备状态、菠菜鸡蛋面演示步骤。均明确标注演示数据；没有联网、凭证、真实食材读取或库存写入。演示菜谱不根据真实家庭情况生成。

交互：GPIO4上页，GPIO5下页，GPIO13操作。前三个主页面循环，菜谱页操作进入步骤，步骤操作返回菜谱，食材页操作进入菜谱，状态页操作回食材。实体上/中/下对应哪个GPIO尚未确认，请以实际功能观察，不能把SW编号当GPIO编号。

全刷完成后至少等15秒才执行下次刷新。间隔内事件合并到最后请求页；回到当前页不会刷。刷新期间驱动阻塞约数秒，此时不采集按键；刷新后同步电平避免重放长按。屏幕没有即时动画。不要连续按，按一次等待约20秒看结果。

串口115200：p上页，n下页，a操作，s查看请求页/已显示页/累计按键及刷新次数。串口命令和实体按键调用同一页面状态逻辑，串口验证不能代替实体按键验收。

## 构建
ESP32 core3.1.0，GxEPD2 1.6.9及Adafruit GFX依赖；AirM2M_CORE_ESP32C3，4MB Flash。打开本目录FridgeDemo.ino并保留所有.h/.cpp，然后编译上传COM4（端口需要确认）。
中文由电脑生成400x300的1位图，每页15000字节；设备不加载中文字库。tools/fridge_demo/generate.py使用Pillow及Windows微软雅黑生成DemoPages.h和preview/*.png，可用--font指定其他支持中文的字体。更改演示文字后重跑脚本并重新编译。

此版本监听按键，ESP32不深睡；屏幕刷新后hibernate。未做电池续航验证，不作为省电正式版。

2026-11-07验证：已编译上传COM4；串口n/a/p/n走完0→1→3→2→0，5次累计刷新，重复刷屏调用约4.46秒，等待约4.08秒。尚待用户目视及实体按键翻页验收。
