东西都放在哪儿

现在的架构、几百个菜谱该放哪、识别模型该放哪、以及"家庭码为什么没有"。

一、现在只有一层：静态托管

一句话：现在是纯前端。网页、菜谱、模型都能静态托管；只有"多台手机共享、账号、云端识别"才需要后端。

二、几百个菜谱放哪：data.js 换成 data/recipes.json

放什么放哪多大现在
菜谱（300–400 道）data/recipes.json，页面 fetch 加载约 300–600 KB20 道，写在 data.js 里
食材表data/foods.json约 30 KB25 种
常备调味data/pantry.json< 5 KB19 种
识别模型models/*.tflite 或 .onnx5–20 MB还没放
用户数据浏览器 localStorage（未同步）< 100 KB有，但只在本机

为什么不需要数据库：菜谱是"只读内容"，永远不变，用文件最合适。400 道菜 600 KB，手机上加载不到一秒。数据库（SQLite/Postgres）只有到"多用户写入"时才需要。

真要放几百道时的正确做法：

  • 用我已经写好的抓取脚本（parse_htc2.py）从 HowToCook 批量拉，清洗成 JSON；
  • 按品类拆成 recipes/meat.json、recipes/veg.json…，首页只加载索引（菜名+食材 id+热量），点开才拉详情；
  • 真正的工作量不是"放"，是"对上食材 id"：374 道菜里出现的配料有几百种写法（"猪瘦肉/里脊/五花肉"），不做映射就没法跟冰箱对上。这一步大概要一天。

三、识别模型放哪：两条路，选一条

路线模型放哪优点代价
端侧（推荐先做） models/food8.tflite，和网页一起托管 离线可用、零服务器成本、拍照不出手机 只能识别你训练的那几类（8–10 类），精度取决于拍的样本
云端 服务器 / 云函数（阿里云、腾讯云、Cloudflare Worker） 能认几百类，精度高（百度/腾讯的果蔬识别 API） 要后端 + API Key + 费用 + 网络；App 没有后端，所以现在走不通

现在 gate.html 里的手部检测模型是从 CDN（storage.googleapis.com）拉的 —— 能跑，但依赖外网。等你真要离线演示，把那个 .task 文件也放进 models/ 就行，代码只改一行路径。

四、"家庭码为什么没有"——因为真的需要后端

家庭码本身只是一串字符，存在 localStorage 里当然能显示（现在就是这样）。但它一点都不"生效"：两台手机各自 localStorage，谁也看不到谁。

要做到需要什么现在
两台手机看到同一个冰箱一个地方存「家庭 → 物品列表」+ 同步机制（轮询/WebSocket）没有
墨水屏读到手机加的东西同一份数据 + 一个拉取接口同机同浏览器能演示
谁放了什么（by 字段）账号或至少"设备昵称"字段已留，值只有本机

最便宜的可行后端（如果真要做）：Supabase / Firebase 免费额度就够 —— 一张 household_items 表 + 匿名登录，半天接完，不用自己写服务器。这也是我建议的下一步，但不建议在周一之前动。

演示时正确的说法："多用户的信息模型已经验证（一屏多端、谁放了什么、共享决定），同步层是下一个工程步骤。" —— 这句话是真的，而且听起来像工程师说的话。

五、结论：三张清单

现在能放放哪
菜谱（几百道）data/*.json + fetch
识别模型（端侧）models/*.tflite
手部检测模型（离线化）models/hand.task
网页、样式、图标仓库根目录
必须要有后端才能做建议时间
多手机共享一个冰箱（家庭码真正生效）交完作业再做，Supabase 半天
账号 / 采纳日志跨设备汇总同上
云端高精度识别有预算再说

一个数字提醒：GitHub Pages 单文件上限 100 MB、仓库建议 < 1 GB。菜谱和 20 MB 以内的模型完全没问题。
