# 让冰箱屏和 App 在深圳可用 · 方案与现状

> 2026-11-11。先读这一页再看别的。

## 一个必须先讲清的事实

**不只是墨水屏连不上，App 也一样。**

App 的数据请求打的是 `https://zbrvcwxwecorjdzqltxg.supabase.co`（Auth / REST / Edge Functions），
这块域名在深圳线路会被按 SNI 重置。所以妈妈在深圳打开网页，登录和库存都拿不到；
墨水屏也是同一个原因。**修一处，两处一起好。**

## 目标拓扑（一句话）

```
深圳家里                         香港/新加坡                     Supabase
─────────                        ────────────                  ────────
墨水屏 ──HTTPS──▶  fridge.你的域名 ──反代──▶ functions/v1/fridge-frame
妈妈手机 ─HTTPS──▶ supa.你的域名   ──反代──▶ /auth/v1  /rest/v1  /functions/v1
```

中继机器必须**同时**能到 Supabase、又能被国内访问，所以位置只能是香港/新加坡/日本。

## 分三步，越往后越贵

| 步 | 做什么 | 花费 | 能否跳过 |
|---|---|---|---|
| 1 | **买一个域名**（.com/.xyz，阿里云/腾讯云/Namesilo） | ¥30–80/年 | ❌ 不能，`*.workers.dev` 在国内被墙 |
| 2 | 域名托管到 Cloudflare，部署两个 Worker：`fridge-*`（已有）与 `supa-*`（通用反代，待写） | ¥0 | 可以，但 CF 国内线路时好时坏 |
| 3 | 换成腾讯云轻量·香港（¥99/年，2核2G 30M/1TB）+ Caddy 自动 HTTPS | ¥99/年 | 想稳定就别跳 |

**务实建议**：先做 1+2 验证深圳能不能通（总成本 ¥30–80/年）；能通但发抖，再上第 3 步。

## 改两个配置就行

| 位置 | 改什么 |
|---|---|
| 固件 `fridge_secrets.h` | `FRIDGE_FRAME_URL` → `https://fridge.你的域名/`（**结尾必须带 /**） |
| App `sync.js` 的默认配置 / 设置页里的 Project URL | → `https://supa.你的域名` |

固件注意两点（已踩）：请求必须带 `User-Agent`（否则 Cloudflare 1010），中转换域名要换根证书或改用内置 CA 包。

## AI 现在为什么需要电脑常开

「今天的锅」的 AI 现配菜走的是本机链路：

```
浏览器 → cloudflared 隧道 → 本机 server.py:8941 → Ollama(127.0.0.1:11434, qwen2.5vl:3b) → 返回 JSON
```

`server.py` 和 Ollama 都在你的电脑上，所以电脑一关就没了。识别（拍照认食材）不受影响，
那是手机浏览器里的 TFLite，本来就不依赖电脑。

### 上云的四种走法

| 方案 | 要什么 | 成本 | 评价 |
|---|---|---|---|
| **A. 换云端 API（推荐）** | DeepSeek / 通义 / 智谱 的 key | 按量，一道菜约 ¥0.001 | 不用服务器；key 放 Supabase Edge Function 里，不下发浏览器 |
| B. 把 Ollama 搬上服务器 | 带 GPU 的机器 | ¥1000+/月起 | 不划算 |
| C. 保持本机 | 电脑常开 | ¥0 | 现在这样，老家没人会开电脑 |
| D. 混合 | 文本走 API、识别继续端侧 | 几元/月 | 最省事，和 A 基本一样 |

**建议 A/D**：把 `server.py` 里"生成菜谱"那一段改成调用云端 API，做成一个 Edge Function（`ai-recipe`），
浏览器只调函数、不持 key。注意：Edge Function 同样在国内不可达，所以它必须挂在上面的中继域名下。
