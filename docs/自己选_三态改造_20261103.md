# 「自己选 / 今天的锅」三态改造（2026-11-03）

## 三个状态

| 状态 | 食材区 | 锅 / 结果区 | 底部 |
|---|---|---|---|
| A 选食材 | 三列紧凑网格，限高内部可滚，可「展开全部」 | 空锅 + 已选标签 | 帮我做一道菜 |
| B 生成中 | 收起 | 骨架卡 + 锅放大、蒸汽 | 「正在为你寻找合适的做法……」 |
| C 出结果 | 收成一行「已选：豆腐 · 猪肉 · 修改」 | 成品菜主卡（图/名/时间/匹配/缺料/做法） | 开始做饭 · 换一道 · 收藏 · 重新选 |

状态由 `document.body.dataset.state` 控制，DOM 只有一套，`sel / curList / curGoal` 全程不重建。

## 关键实现

- `setState(s)`：只在 select / loading / result 之间切 `hidden`，不改数据。
- `generate()` 存 `curList`（前三道）和 `curIdx`；`换一道` 在 `curList` 里轮转，不重新请求。
- 主卡 `heroCard()` 复用了原来的 `.rcard` 内容；备选是横滑小卡，点一下换主卡。
- 结果态底部条直接调原来的 `cook(recipe, btn)`，库存扣减、Supabase 推送、日志都不变。
- 收藏沿用 `FD.favAdd/FD.favRemove`，`type:"lib"`，重复点变成「已收藏」。
- 食材区高度按锅面板实际上沿计算（`markCut`），选中食材让面板变高时会重算。

## 经典菜收藏

- `type:"classic"`，key 是 `cl:<id>`；存 name / minutes / tech / tip / cuisine / sig / need。
- 入口：锅页面经典菜弹层里的「收藏这道」。
- 查看：菜谱页「收藏」里是一张绿色虚线卡，点开有技法步骤、缺什么、移出收藏、小红书入口。

## 已知边界

- 主卡「开始做饭」在底部条，不再重复放在卡里。
- 经典菜（词表里的菜）还不能「开始做」，没有数量可扣。
- 内部滚动区在 iOS 上用的是 `-webkit-overflow-scrolling:touch` + `overscroll-behavior:contain`，需要在真机再确认一次。
