# 本地经典菜：词表 + 技法卡（2026-11-03）

不接 AI 也能回答「豆腐 + 猪肉能做什么」——答案是**酿豆腐**，不是「豆腐炒肉」。

## 为什么不是写一套搭配引擎

- 3B 模型的问题不是不会写步骤，是**不会起名**：问「用豆腐和猪肉做一道菜」它给「豆腐猪肉炖」；问「写一道客家酿豆腐」步骤立刻正确。
- 规则引擎自动拼步骤，火候和用量都是猜的，读起来像说明书，维护成本还高。
- 所以缺的是**菜名知识**这一层，补上它，剩下两条路都通：库里有真菜谱、库里没有就用技法卡。

## 两个文件

| 文件 | 内容 | 怎么加 |
|---|---|---|
| `dishes.js` | 50 条经典菜：`{id, n, sig, need, tech, cuisine, min, lib, tip}` | 加一行，`sig` 用 `data.js` 里的食材 id |
| `techniques.js` | 3 张技法卡：酿 / 红烧 / 清蒸，各 5–6 步 + 3 条关键点 | 加一张卡，`dishes.js` 里 `tech` 指向它 |

字段说明：

- `sig`：必须用到的食材，锅里全有才算命中
- `need`：这道菜还缺的关键食材，用来显示「还差 1 样」
- `tech`：做法归属；没有对应卡就只显示 `tip` 一句要点
- `lib`：菜谱库里已有的同名菜；**有 lib 的条目在锅里不会重复出现**，因为库里的结果已经覆盖

## 匹配规则（cook.js · classicFor）

1. `sig` 全部在锅里 → 命中
2. 库里有同名菜 → 跳过（上面三张结果卡已经给了）
3. 锅里选了 3 样以上时，只用上一样的（`sig.length < 2`）不算「用这几样」
4. 排序：缺得少的优先 → 用得多的优先 → 时间短的优先，最多 4 道

## 界面

- 结果区下方一排可横滑的小卡：「用这几样还能做 N 道」
- 点开是底部弹层：食材（有/缺）、做法（技法卡 5–6 步）、关键三点、做法来源
- 只写了要点的菜：显示一句要点 + 小红书 / B 站搜索入口
- AI 卡片措辞：上面已有本地经典菜时，不再说「库里没有」，改成「想再换个吃法？」

## 已知边界

- 技法卡只覆盖酿 / 红烧 / 清蒸；其余菜只有一句要点
- 词表命中的菜**不能点「开始做」**（不扣库存、不记历史），因为还没和库存数量对齐
- 词表 50 条是第一批；扩到 120 条时按「常用食材组合」补，不按菜系补
