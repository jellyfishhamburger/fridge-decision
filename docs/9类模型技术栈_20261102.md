# 端侧食材识别模型 —— 技术栈说明（可直接交给 GPT 做优化建议）

**项目**：磁吸式智能冰箱食材助手（IDAT7211）
**整理日期**：2026-11-02
**这份文档说明的是「我们自己训练的那个 9 类模型」到底怎么做的**，包含全部超参、数据来源、导出方式和端上推理链路。所有数字都来自仓库里的日志和产物，不是回忆。

---

## 0. 一句话

用 **Keras 3 / TensorFlow 2.16（CPU）** 微调 **MobileNetV3Small（ImageNet 预训练）**，做 **9 类单标签分类**（8 种食材 + unknown），训练数据是 **861 张 Wikimedia Commons 网图**，经自制的「手机俯拍」域增强扩到 2,583 张，导出成 **float32 TFLite（uint8 输入包装）**，在浏览器里用 **MediaPipe Tasks Vision** 跑，前端做**三帧投票**后才采信。

真实场景准确率：**13 张有食物的真实照片里判对 8 张（61.5%）**，把 3 张空景也算进去是 **8/16 = 50%**。

## 2. 数据

| 项目 | 实际情况 |
|---|---|
| 来源 | **全部 Wikimedia Commons**（`sources.csv` 861 行，`page` 字段全部是 `commons.wikimedia.org`） |
| 规模 | 8 类 × 60 张 = 480，加 `unknown` 381 张 = **861 张** |
| 类别 | `chili` 辣椒 / `egg` 鸡蛋 / `greens` 青菜 / `milk` 牛奶 / `mushroom` 蘑菇 / `pork` 猪肉 / `tofu` 豆腐 / `tomato` 番茄 / `unknown` |
| 许可 | 21 种（CC BY-SA 3.0、CC BY 3.0、Public domain 等），`sources.csv` 记录了 title / license / artist / page |
| 真实照片 | **0 张参与训练**。她拍的 16 张只做测试集（另有 41 张在 `Desktop\training`） |
| `unknown` 类 | 381 张杂图（`fetch_unknown.py` 抓的），用来教模型说「这不是我认识的东西」 |

**注意两个隐患**：

1. **许可传染性**：CC BY-SA 是**相同方式共享**，训练出来的权重是否算「演绎作品」在法律上有争议。课程作业无所谓，做产品要么换 CC0/PD 图源，要么重新采集自摄图。
2. **域差极大**：网图是「商品图 / 白底 / 摆拍 / 亮光」，她的是「冰箱里 / 手机俯拍 / 暗 / 偏暖 / 有反光」。整个增强模块就是在硬补这个差。

### 增强配方（`make_domain_aug.py`，每张造 3 个变体）

| 步骤 | 参数 |
|---|---|
| 旋转 | ±8°（BICUBIC，expand） |
| 随机裁切 | 保留 72%–90%，中心在画面 42%–58% 浮动，再 resize 到 256 |
| 亮度 | ×0.55–0.95（模拟室内暗光） |
| 对比度 | ×0.85–1.15 |
| 饱和度 | ×0.75–1.10 |
| 色温偏暖 | R ×1.05–1.16，B ×0.92–1.0 |
| 高斯模糊 | 每隔一张加 σ 0.6–1.6（模拟手抖） |
| 暗角 | strength 0.25–0.5（模拟冰箱内壁吃光） |
| JPEG 压缩 | quality 62 / 75 / 88 随机 |

## 3. 模型

```python
base = keras.applications.MobileNetV3Small(
    input_shape=(224, 224, 3), include_top=False,
    weights="imagenet", include_preprocessing=True)   # 归一化在模型内部
x = GlobalAveragePooling2D()(base(i, training=False))
x = Dropout(0.3)(x)
o = Dense(9, activation="softmax")(x)
```

| 项目 | 数值 |
|---|---|
| 总参数 | **944,313（3.60 MB）** |
| 可训练参数（阶段一） | 5,193（只有分类头） |
| 输入 | 224 × 224 × 3，**uint8**，整幅拉伸（不做中心裁切，与训练一致） |
| 输出 | 9 维 softmax |
| 预处理 | `include_preprocessing=True`，即模型内部做 1/127.5 − 1 归一化；**外部不要再归一化** |

## 4. 训练

| 项目 | 设置 |
|---|---|
| 框架 | Keras **3.15.1** / TensorFlow **2.16.2（CPU 版）** / numpy 1.26.4 / Pillow 13.0.0 |
| 数据划分 | 按「原图名」分组（`xxx_a0/_a1/_a2` 落同一侧），80/20 → **train 2,064 / val 519**，seed 42 |
| Batch | 32 |
| 类别权重 | `unknown` = **0.45**，其余 1.0（故意压低 unknown，防止模型把什么都推给 unknown） |
| 阶段一 | 主干冻结，`Adam(1e-3)`，10 epochs，`EarlyStopping(patience=2, monitor=val_accuracy)` |
| 阶段二 | 解冻主干**最后 35 层**，`Adam(3e-5)`，6 epochs，同样早停 |
| 损失 | categorical_crossentropy |

**训练曲线的实际走向**（`_trainaug2.log`）：
- 阶段一 val_accuracy 从 0.54 爬到 **0.67** 左右就平了；
- 阶段二继续到 **≈0.70**，之后开始震荡。

**这意味着**：验证集的 70% 已经是这套数据能给出的上限附近，**继续加 epoch 没用**，瓶颈在数据不在训练时长。

16 张真实照片，**不参与训练**，`food9_aug2_report.json` 逐条记录：

| 4f1433b2 | egg | unknown | 0.42 | ❌ |
| 50123cab | egg | chili | 0.38 | ❌ |
| 5922d41a | egg | egg | 0.79 | ✅ |
| 69b97454 | egg | milk | 0.57 | ❌ |
| 70382138 | unknown | milk | 0.76 | ❌ |
| 8bb5cae4 | milk | milk | 0.52 | ✅ |
| 8ea80782 | milk | milk | 0.40 | ✅ |
| a76dfd53 | none（空景） | milk | 0.48 | ❌ |
| ba2fb203 | pork | pork | 0.80 | ✅ |
| bf38979b | none（空景） | milk | 0.58 | ❌ |
| c88c996b | unknown | milk | 0.32 | ❌ |
| e9a0464d | milk | milk | 0.46 | ✅ |
| f96e414d | pork | pork | 0.49 | ✅ |

**结论性观察**（这几条是优化时最该看的）：

1. **「牛奶」是吸铁石**：7 次错误里有 4 次判成 milk（含 3 张空景全判 milk）。典型的**类先验失衡**——牛奶图（白包装）在增强后高频、低对比，模型学会了「看不清 → 猜 milk」。
2. **置信度不可用**：正确答案的置信度低到 0.40–0.52，错误答案反而有 0.76/0.58。**softmax 置信度与正确性几乎不相关**，所以前端那套「≥0.45 才收」的阈值其实是在瞎猜。
3. **unknown 类没学会"拒绝"**：3 张空景没有一张被判成 unknown。
4. 早期版本更差（最初 1/11，改增强后 6/13，再调 8/13），**说明域增强这条路是有效的，但已经到边际**。

## 6. 导出与端上推理

### 导出（`export_food9d_u8.py`）

```python
inp = Input(shape=(224,224,3), dtype="uint8")          # MediaPipe 要求 uint8 输入
x   = Lambda(lambda t: tf.cast(t, tf.float32))(inp)    # 内部转 float
wrapped = Model(inp, base(x))
wrapped.export(tmp, format="tf_saved_model")           # 必须走 SavedModel
tflite = TFLiteConverter.from_saved_model(tmp).convert()
```

| 项目 | 值 |
|---|---|
| 文件 | `models/food9d_u8.tflite`，**3.76 MB** |
| 量化 | **无量化**（float32 权重；uint8 只是输入层的 cast） |
| 踩过的坑 | ① `from_keras_model` 会触发 LLVM 崩，必须走 `from_saved_model`；② TF 打不开含中文的路径，要先导到 ASCII 临时目录再拷回 |
| 一致性校验 | uint8 TFLite 与 Keras float 预测在 45 张上逐一比对，结果一致 |

### 端上（`classifier.js`）

| 项目 | 值 |
|---|---|
| 运行时 | **MediaPipe Tasks Vision**（`vendor/mediapipe/vision_bundle.mjs`，本地自带，无 CDN） |
| 接口 | `ImageClassifier.createFromOptions({ runningMode:"IMAGE", maxResults:3, scoreThreshold:0 })` |
| 委托 | 先试 **CPU**，失败才回 GPU（GPU delegate 在桌面/无头 Chrome 上经常 Open 失败） |
| 预处理 | `drawImage(src, 0,0,w,h, 0,0,224,224)` —— **整幅拉伸，不裁切** |
| 三帧投票 | 连拍 3 帧（间隔 320ms）；拉普拉斯方差 < 45 的糊帧丢弃；**≥2 帧一致** 且 **平均置信 ≥0.45** 且 **与第二名差 ≥0.12** 才采信 |

## 8. 已知限制（建议 GPT 从这几条切入）

| # | 问题 | 影响 |
|---|---|---|
| 1 | **单标签分类**，一张图只能给一个答案 | 冰箱里同时出现多样时无法一次识别；现在靠用户「逐件拍」规避 |
| 2 | **只有 9 类**，第 9 类是 unknown | 覆盖不了「几乎所有种类」，这是产品目标的核心矛盾 |
| 3 | 训练图全是网图，真实照片 0 张进训练 | 域差靠增强硬补，已到边际 |
| 4 | **牛奶类先验过强** | 4/7 的错误都是「猜牛奶」 |
| 5 | **置信度不可校准** | 0.76 的预测是错的，0.40 的预测是对的，阈值形同虚设 |
| 6 | 空景/无食物没有专门类别 | 3 张空景全部误报 |
| 7 | 未做量化 | 3.76MB float32，可 int8 压到 ~1MB 并提速，但有掉点风险 |
| 8 | 训练图许可含 CC BY-SA | 商用有传染性风险 |
| 9 | 224×224 整幅拉伸 | 长条形（如牛奶盒、青菜）变形明显 |
| 10 | 验证集与训练集同分布（同一批图的增强） | 70% 的 val_accuracy 偏乐观，真实只有 61.5% |

```bash
# 2) 训练（两阶段）

python _build/export_food9d_u8.py

```
