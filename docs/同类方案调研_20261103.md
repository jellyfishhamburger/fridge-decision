# 同类方案调研：别人做到哪一步了

> 2026-11-03 · 检索平台：GitHub / YouTube / Bilibili / HN / 学术库（ACM、MIT Media Lab、Frontiers、arXiv）/ 商业产品评测
> 目的：找出可以**直接抄架构**的项目、可以**引用**的研究、以及我们**不要踩**的坑。
> 标注：✅ = 我读过原文/README；◻︎ = 只看到标题与摘要（够判断，引用前自己点开确认）。

---

## 0. 三句话结论

1. **冰箱端的墨水屏提醒，已经有人做成了成熟开源项目**（inkpanel、PaperMono）和商品（reTerminal Sticky、BITMOLAB Quoter/0）。"服务器渲染一帧、面板只下载"的架构不用我们发明，可以直接抄。
2. **把菜谱投影到台面/砧板上，是 MIT 二十年前做完的研究**（CounterActive、CounterIntelligence、AR Kitchen），始终停在实验室；商业上没人做成——原因和我们算的一样（亮度、遮挡、对位）。
3. **"冰箱上一块大屏"被商业反复证明是能卖、但没人爱**（Samsung 32″ Family Hub 被评"就是把一块平板粘在冰箱上"；云米大屏因强制广告上热搜）。**越小、越不像屏，越对。**

## 1. 冰箱端（提醒 / 库存）：架构可以直接抄

| 项目 | 平台 | 他们做了什么 | 可抄 / 注意 |
|---|---|---|---|
| **inkpanel** ✅ MIT | GitHub | 服务器采集数据 → 按面板配置渲染 **1-bit 帧缓冲** → 面板唤醒后取帧，内容没变返回 `304`，**只在变化时才刷新**，然后深睡 | **这就是我们"门贴是哑终端"的现成实现**。抄它的 304 判断 + 只在变化时刷 + 深睡调度；固件端真的只剩"下载 + 贴图" |
| **PaperMono** ✅ GPL-3.0 | GitHub + HN | M5Stack PaperMono（ESP32-S3 + **3.97″ 480×800 触摸墨水屏**）+ FastAPI 服务 + **手机网页当后台**，做成冰箱上的购物清单；约 2400 行 C++ | 抄：手机网页即后台（我们的 PWA 天然适配）、按货架分组、**每 10 次局部刷新强制一次全刷防残影**。注意：GPL，别把代码直接搬进要闭源的东西 |
| **reTerminal Sticky** ◻︎ | 商品 / XDA | $50 的 3.97″ 墨水屏冰箱贴，按键说话留语音便签，磁吸在冰箱上 | 证明"冰箱贴 + 墨水屏"这个品类成立；抄它的磁吸结构和"按一下就说"的单动作交互 |
| **BITMOLAB Quoter/0** ◻︎ | 商品 / B站 | 磁吸墨水屏便签，**NFC 一贴唤醒**、可自定义 API 内容 | 抄 **NFC 触发**（比蓝牙配对稳，手机一贴就推一屏），适合"买菜回来贴一下更新清单" |
| **E-Ink Recipe Frame** ◻︎ | 个人项目 | 用 Inkplate 10（9.7″ 墨水屏）做成电子相框，摆着看菜谱 | 说明"菜谱框"这个形态有人做过，但它是大屏 + 靠手机翻页；我们做 4″ 一步一屏正好相反 |
| **Cooklang / Pi 厨房屏** ✅ | 博客 + GitHub | Raspberry Pi 4/5 + 7″ 触摸屏跑 CookCLI，局域网里任何设备都能看菜谱 | 抄：Pi + 网页的最小系统；注意它是"触摸大屏"，正是我们不想要的形态 |

**软件侧已经很挤**：GitHub 上一堆"冰箱库存/保质期"项目（Fridge9000、FreshGuard、fridge-track、GhostPantry、pantrie、AIoT-Smart-Fridge），**全是手机/网页，没有一个做硬件**。这反而说明：硬件端还是空位。

**我们和它们的差别**：它们做的都是"清单 / 便签 / 购物"，**没有一个把"今晚该吃哪道菜"这个决策放到冰箱门上**。

## 2. 做饭端：研究做完了，产品没成

| 项目 | 平台 | 他们做了什么 | 结论 |
|---|---|---|---|
| **CounterActive** ✅ MIT Media Lab | 论文 PDF | 把菜谱**投影在厨房台面上**，用电场感应 + RFID 识别你"按到哪个词"，可以按自己的节奏走菜谱、点开视频 | **组员想的投影方案，20 年前就完整做过**。它没变成产品，不是没人想到，是亮度/遮挡/对位没解决 |
| **CounterIntelligence / AR Kitchen** ◻︎ | MIT / UIST 2004 | 把信息投到厨房的物体和表面；五个子系统分别盯冰箱、灶台、水槽 | 同上；一个厨房要五套系统，正说明"投影覆盖全流程"的成本 |
| **PersonalChef** ◻︎ | CHI 2010 | 双视角、多屏的厨房台面，一步一步教做菜 | "一步一屏"的信息设计早就被验证；但它靠多块屏，不是一块 |
| **Cook's Collage** ◻︎ | HOIT 2005 | 把"你刚才做了什么"回放给你看 | 记录型交互的先例，和我们的"确认入库"是一类思路 |
| **方太 滑盖折叠屏** ◻︎ | 商品 | 厨电上做**滑盖折叠屏**：用时升起，不用时藏进机身 | **"用完消失"这个机构已经被产业认可**，可以借它的形态语言（下翻/滑盖），不用自己发明 |
| **Kitchen Display Systems** ◻︎ | 商品 | 卖 15–17″ 的备餐/菜谱屏 + 专用支架，挂在**眼高** | 商业厨房的答案就是"屏幕挂眼高"；反证我们的方向对，只是尺寸从 15″ 缩到 4″ |
| **even-kitchen** ✅ | GitHub | 给 Even Realities G2 眼镜做的做饭助手：菜谱列表、逐步指引、**每步独立计时** | 眼镜这条路已经有开源实现，但它绑死一款小众眼镜；大厂（Meta Ray-Ban 的 Cook）正在做，我们做不过 |
| **Meta Cook app** ◻︎ | 产品页 | 在 Ray-Ban Display 上"一次一大步"地显示菜谱 | 再次证明"一步一句话"的信息设计是对的——但它不是我们要做的硬件 |

**这一栏的总结**：投影 = 实验室天花板；大屏 = 商业厨房的做法；眼镜 = 大厂在做。**中间那块"小、挂眼高、不用手"的位置是空的。**

## 3. 交互：脚踏是成熟品类，不是脑洞

| 项目 | 平台 | 他们做了什么 | 可抄 |
|---|---|---|---|
| **AirTurn DUO500** ◻︎ $109 | 亚马逊 | 乐手翻谱用的**静音蓝牙双踏板**，连 iPad/手机，模拟方向键 | 证明"手上没空就用脚翻页"被验证了二十年；我们只需换个叙事（厨房） |
| **PageFlip Butterfly / Donner / Stomp** ◻︎ | 亚马逊 / YouTube | 同类产品，¥50–200 区间也有 | 买一个拆开装壳，是最省事的 MVP |
| **DIY BLE 翻页踏板** ◻︎ | Instructables | 用 Bluefruit EZ-Key 模块做蓝牙 HID 踏板 | 和我们"puck 做成 USB/BLE 键盘"是同一条路，代码量很小 |
| **GestuCook** ◻︎ | GitHub | 手势控制的菜谱助手（摄像头识别手势翻页） | 手势在油烟和蒸汽里误触发高；只当备选 |

## 4. 冰箱内摄像头：学术界的结论和我们一致

| 来源 | 结论 |
|---|---|
| **SmrtFridge**（ACM BuildSys 2019） ◻︎ | 冰箱内 RGB 摄像头**无法估算不透明容器的数量**、**遮挡严重**，所以他们改用"用户交互驱动"的称重方案 |
| **Frontiers AI 2024**：冰箱食物识别 ◻︎ | 深度学习识别在受控数据集上可行，真实冰箱的遮挡/光照仍是主要误差来源 |
| **Food det**（Neurocomputing 2019） ◻︎ | 专门做"冰箱内多类食物检测"，说明这是独立的研究问题，不是调个模型就行 |
| **arXiv 2509.07400**：ESP32-CAM 拍冰箱内部 ◻︎ | 便宜模组 + 限定类别（蔬菜）的路线；正好印证"模组能拍，但类别必须收窄" |

**用法**：报告里写"不承诺放进去自动记录"时，引 SmrtFridge 这一条就够——**这不是我们做不出来，是这类传感器在物理上就到这**。

## 5. 大屏冰箱：商业上的反面教材

| 案例 | 事实 | 启示 |
|---|---|---|
| **Samsung Family Hub 32″** ◻︎ | 多家评测的共同评价：这块触屏"本质上就是一块巨大的平板粘在冰箱上"；How-To Geek 直接建议"别买智能冰箱，买冰箱 + iPad" | 屏越大越像广告位；"智能"不等于"多一块屏" |
| **云米大屏冰箱** ◻︎ | 因**强制推送购物广告且无法关闭**上热搜 | 屏幕一旦成为流量入口，就会背叛用户；我们的面板必须"只显示自己的数据" |
| **MIT Tech Review（2011）** ◻︎ | 早在那年就在问"我们真的需要一台 Android 冰箱吗" | 这个坑存在十五年了 |

## 6. 透明显示（你自己那条线）：有现成实现，但没有"厨房版"

| 项目 | 平台 | 说明 |
|---|---|---|
| **HoloCubic（稚晖君）** ◻︎ | GitHub / B站 | 1.5–2″ 屏 + 45° 分光棱镜 + 透明壳；有完整教程、AIO 固件、避坑指南 |
| **3.2″ 升级版** ◻︎ | B站 | 有人已经把它做大到 3.2″，说明"加大"可行；4″ 没有套件，要自己配屏和分光镜 |
| **自制全透明显示器** ◻︎ | B站 | 用透明屏/分光方案做"透明显示器"，可以看它的结构件做法 |
| **HoloPOT V2** ◻︎ | YouTube | 低成本 360° 裸眼 3D 转盘，另一种"不用眼镜"的显示思路 |

**结论**：透明立方/画框的**光学和结构都有现成参考**，但**没有人把它放进厨房、也没有人用它显示"一步菜谱"**——这是我们的形态创新点，风险在亮度和清洁，不在"做不出来"。

## 7. 值得抄的三件事 + 我们的空位

### 抄这三件

1. **inkpanel 的"服务器渲染 + 304 + 只在变化时刷"** —— 门贴固件可以薄到 200 行，改版不用重烧。
2. **PaperMono 的"手机网页就是后台"** —— 我们已经有 PWA 和 Supabase，天生就是它的升级版。
3. **AirTurn 的脚踏形态** —— 买一个现成的拆开装壳，或自己用 BLE HID 做，都是两周内能完成的事。

### 我们的空位（这轮检索里没找到对应物）

- 冰箱屏：别人做"清单/便签/购物"，**没人做"今晚吃哪道菜"的决策**。
- 做饭屏：别人解决"看什么"，**没人把"光 + 声 + 脚"当成一套全向通道**来设计。
- **拍位（可拆的固定光学工位）在调研里没有对应物**——所有冰箱摄像头项目都在冰箱**内部**，没人做"门外侧的俯拍工位"。

---

## 8. 组会上引用这三条就够

1. **CounterActive（MIT）**：投影菜谱是 20 年前的研究原型，不是我们不敢做。
2. **SmrtFridge（ACM BuildSys 2019）**：冰箱内摄像头做不了数量与遮挡，这是传感器物理限制。
3. **AirTurn**：手上没空就用脚，是成熟交互，不是我们的怪点子。
